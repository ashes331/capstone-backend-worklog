핵심 수정 코드

1. 사람이 탄 휠체어가 wheelchair로 학습되지 않던 문제

원본 데이터셋에서 people_wheelchair만 있는 이미지가 496장, wheelchair만 있는 이미지가 379장, 둘 다 있는 이미지는 2장뿐이었습니다. person 박스만 남기고 wheelchair 박스를 남기지 않아, 모델이 wheelchair를 빈 휠체어 사진으로만 배웠습니다. 원래의 느슨한 박스를 wheelchair로도 남겼습니다.

ai_modules/cv/wheelchair_training/scripts/pseudo_label_wheelchair.py
for j, ok in enumerate(resolved_flags):
... # person 박스는 검출 결과로 교체, 실패하면 원본 박스를 폴백
wheelchair_px = wheelchair_px + pw_px

2. pseudo-labeling 박스 좌표 스케일

모델 출력 좌표가 이미 0~1로 정규화되어 있는데 입력 해상도(320) 기준 픽셀로 착각해 다시 스케일링해서, 874건 전부 매칭에 실패했습니다.

ai_modules/cv/wheelchair_training/scripts/tflite_person_detector.py
sx, sy = img_w / self._w, img_h / self._h
x1 = (cx - w / 2) * sx
x1 = (cx - w / 2) * img_w

4. 훅이 매 렌더마다 재연결되던 문제

훅의 useEffect가 콜백을 의존성으로 쓰는데, 매 렌더 새 화살표 함수를 넘기면 제스처 HUD 때문에 자주 리렌더되는 App에서 카메라와 WebSocket이 계속 끊겼다 다시 연결됩니다.

frontend/src/App.jsx
useApproachDetector({
enabled: true,
onModeAction: (action) => { if (action === 'gesture') setGestureEnabled(true) },
})
const handleApproachModeAction = useCallback((action) => {
if (action === 'gesture') setGestureEnabled(true)
}, [])
useApproachDetector({ enabled: true, onModeAction: handleApproachModeAction })

5. 안내 종료 후 재시작 잠금

안내 3회 완료 또는 터치로 끝나면 잠금 상태로 두고, 대상이 연속 6프레임(약 3초) 사라져야 다시 감지합니다. 안내 중일 때만 터치가 잠금을 겁니다.

작업 흐름

  1. 계획서·기획 문서 대조

    작업 계획서, Issue #66, 팀 기획 대화록(docs/AI 질의.md)을 대조해 3클래스 재학습과 "휠체어 → 제스처 모드" 설계를 확정.

  2. 데이터셋 분석

    라벨 파일을 직접 세어 계획서의 가정("person 라벨 없음")이 틀렸고, 사람이 탄 휠체어만 별도 클래스의 느슨한 박스로 라벨링되어 있음을 확인.

  3. Pseudo-labeling · 병합 · 1차 학습(v1)

    구모델로 person 박스 정제(73% 성공), 두 데이터셋을 person=0, white_cane=1, wheelchair=2로 병합하고 오버샘플링 후 80 epoch 학습, INT8 양자화.

  4. 백엔드·프론트 연동

    감지기를 3클래스로 재작성하고 트리거별 안내·모드 액션을 추가, 훅을 App.jsx에 최초로 연결.

  5. 실사용 테스트에서 문제 발견

    사람이 탄 휠체어가 거의 감지되지 않음(0.0001~0.02). 검증 mAP는 높았지만 val 셋이 같은 좁은 분포라 가려져 있었음.

  6. 데이터 수정 · 재학습(v2)

    wheelchair 박스를 함께 남기도록 pseudo-labeling을 고쳐 재학습·재양자화, 프로덕션 모델 교체 후 같은 사진으로 재검증(0.89~0.92).

  7. 검증 · 형상관리

    WebSocket 시나리오와 프론트 빌드 확인, 감지 훅 재연결 버그와 안내 무한 반복 수정, 커밋 4건 push 후 PR #73 생성.

발견한 문제

9건
사람이 탄 휠체어가 wheelchair로 학습되지 않음
1차 pseudo-labeling이 people_wheelchair를 person으로만 바꾸고 wheelchair 박스를 남기지 않아, 실사용에서 사람이 탄 휠체어가 거의 감지되지 않았음. 검증 mAP로는 드러나지 않았고 실사진 테스트에서 발견
구모델 클래스 순서가 배포 코드와 반대
구모델은 class0 = white_cane, class1 = person인데 approach_detector.py는 WHITE_CANE_CLASS_ID = 1. 정답 박스 816개 위치에서 통계로 확인. 모델 교체와 함께 해소
useApproachDetector가 어디에도 연결되어 있지 않음
기획 문서엔 시각장애인 쪽이 "완료"로 적혀 있었지만 훅은 정의만 있고 쓰이지 않았음. 이번에 App.jsx에 처음 연결
pseudo-labeling 좌표 스케일 오류 (제 코드)
정규화된 출력 좌표를 입력 해상도 픽셀로 착각해 다시 스케일링, 874건 전부 매칭 실패
교체한 신모델을 pseudo-labeling이 다시 읽음 (제 작업 순서)
프로덕션 모델 경로를 신모델로 교체한 뒤 재학습용 pseudo-labeling을 돌리자 구모델이 아닌 신모델(클래스 순서 다름)을 읽어 또 0건. git 히스토리에서 구모델을 복원해 별도 경로로 분리
Windows에서 tflite 변환이 막힘
최신 ultralytics의 LiteRT export가 Windows 미지원 → 8.3.40 고정, tflite_support는 C++ 컴파일러 필요(메타데이터만 실패, INT8 변환은 정상), numpy 2.x의 np.trapz 제거로 학습 중 검증이 죽어 shim 추가
훅이 매 렌더마다 카메라·WebSocket 재연결 (제 연동 코드)
콜백을 의존성으로 쓰는 useEffect에 매 렌더 새 함수를 넘겨, 자주 리렌더되는 App에서 연결이 계속 끊겼다 다시 맺어짐. useCallback으로 참조를 고정
안내가 끝없이 반복되고 터치해도 멈추지 않음
안내 3회 종료 후에도 대상이 화면에 있으면 다음 프레임에서 바로 재시작(7초 테스트에서 안내 18회), 터치 종료 ack 후에도 재시작. App.jsx가 notifyUserInput을 호출하지도 않았음. 종료 시 잠금을 걸고 대상이 연속 약 3초 사라져야 해제하도록 수정(임시 조건), 터치·클릭을 훅에 연결
데이터셋 폴더 혼동 (제 검증 실수)
visionguide_dataset 루트의 images/·labels/(white_cane만, 9,308장)와 실제 학습용 train/·val/·test/가 따로 있는데 루트로 검증해 "person 라벨 0개"라는 잘못된 결론을 얻었음
